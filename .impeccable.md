# Impeccable Design Context

## Design Context

### Users
Two audiences, one page. Primary: hiring managers and recruiters for Senior/Staff
Product Data Scientist roles in Search & Ranking — they skim during a workday at a
desk, deciding in ~40 seconds whether this person owns problems end-to-end.
Secondary: fellow builders and AI-development practitioners who arrive from GitHub
or a demo link and want to see how the work is made.

The job to be done: prove, with inspectable evidence, that the owner turns messy
search behavior into ranked, trustworthy signal — and that she ships real systems
by directing AI agents, not just writing notebooks.

### Brand Personality
Curious, rigorous, hands-on. The feeling of a search-relevance lab notebook that
comes alive: playful in the demonstration, exacting in the claims. Never corporate,
never "AI-startup glossy".

### Aesthetic Direction
"Signal out of noise." The page opens inside the problem space — a dark field of
unranked, drifting documents (WebGL) — and a query brings order: particles rank
themselves into a column. Scrolling lands on warm paper where the evidence reads
like an investigation ledger. Dark hero → light body is a deliberate structural
device, not a theme toggle.

Anti-references: the current v3 broadsheet look (hairline rules + cobalt), the v2
cream+terracotta editorial look, any near-black + neon-accent "AI portfolio",
glassmorphism, hero-metric templates.

### Design Principles
1. The signature element demonstrates the profession — ranking made visible and
   interactive — everything else stays quiet around it.
2. Structure encodes truth: projects read as investigations (Question → Approach →
   Evidence), because that is literally how she works.
3. Claims stay attached to evidence: every project links a live demo, source, or
   artifact. No decoration that implies unearned rigor.
4. Quality floor without announcement: responsive, keyboard focus visible,
   prefers-reduced-motion gets a composed static state, WebGL failure degrades to
   a designed CSS fallback.
5. Vanilla HTML/CSS/JS + vendored three.js only. No build step — the repo deploys
   to GitHub Pages as-is.
